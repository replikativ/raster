# JVM carrier/conversion debt

Numeric declarations, JVM stack categories and source boxing carriers are not
interchangeable. Fixes must preserve conversions, reference identity and input
evaluation order, not merely numerical values on valid inputs.

## Qualification checkpoint — 2026-10-19

The unchanged packed temporal lagged Michaelis–Menten marketing fixture passes
runtime differentiation and actually invoked JVM AOT using the downloaded Raster
0.2.1685 jar, not local source. Two parameter points and two data/row-count cases
agree exactly across those execution paths; all nine coordinates agree with
independent central differences (maximum absolute error about 1.33e-9).
This is bounded model evidence, not general helper, scan/allocation-gradient,
native-C, throughput or allocation qualification. Constructing AOT wrappers
before retaining runtime gradients avoids the separately open mixed-lifecycle
invalidation; no execution guard was reset or numerical call retried.

Native AOT now uses the same definition-input owner as JVM AOT, starting before
frontend analysis and ending at publication. Whole-compilation replacement
retries are distinct from numerical invocation. Recovered absent/present-zero
pullback tests include actual JVM/native calls and higher-order composition.

Product representation is still open: moving a vector field into a primitive
local can lose the original Object input context and rebox it at each later
reference observation. A local Object-completion prototype fixes the JVM
identity counterexample, but remains held because the existing numeric native
acceptance cases need a sound payload projection. An identity-function blacklist
or deleting boxes solely from logical dtype is not that projection.

The earlier helper-boundary development notes below are historical. They explain
the ownership obligations, not a claim that the qualified public marketing path
still has the original admission failure or that all other paths are complete.

## Historical helper composition and owned call regions

The helper-based marketing density exposes a source-AD preparation gap: a
nested helper in a lexical `let` tail can reach the reverse pass after composite
expansion has finished. The bare expression and an explicitly let-bound helper
can work while that enclosing-let spelling fails with
`:ad-unowned-derived-pullback`. Passing those narrower spellings is not complete
helper-composition coverage.

Moving generic ANF earlier is insufficient. For a typed invocation whose first
input needs null/unboxing checks, lifting a later argument's array read can
change both the first exception and observable effects. Normalization must own
the original receiver, exact Method, original input contexts and actual source
compilation policy before flattening the call. Trivial ANF arguments are not
evidence that their original conversions completed.

`prepare-helper-call-region` assembles that existing selected-emission and
ordered-call boundary for generated owners. Its owner-private result keeps
Class ports, the original operands, a combined definition guard, and the paired
helper's executable **and transparent program** together. This is preparation,
not a new runtime, registry, AD rule or default source-AD admission path.

Generated preparation now returns the existing prepared-body/parameter boundary
with a private source-owner sidecar and occurrence-local call regions. Runtime
construction consumes the whole preparation, retaining its actual Class and
executable captures, policy and pre/post-call guards; paired results additionally
guard delayed pullbacks and seed/result carriers. Public runtime construction can
transport such an owner, but the public producer does not yet supply one.
Ordinary inlining, re-differentiation and AOT extraction explicitly refuse an
unprojected owner rather than silently copying its body without the captures.
These private sidecars are not portable IR or cache fingerprints.

Remaining work is to produce the same owner through public `prepare-value+grad`,
implement capture-aware AOT projection, and compose differentiable argument
regions without discarding their original input contexts. Native backends must discharge completion
contracts or refuse them explicitly. Qualification requires the actual marketing
density with changed parameters/data, invoked public JVM AOT, typed conversion
and receiver-order oracles, and existing higher-order/absent-cotangent laws.
The unsafe early-ANF prototype is not enabled by this boundary.

## Nullable numerical values and boxing

Four properties are independent:

| Property | Authority |
| --- | --- |
| Logical numerical dtype | Retained typing and differentiation rules |
| Presence on normal return | Producer/control-flow facts, not the numerical dtype |
| Emitted JVM carrier | Actual method descriptors and emitted stack values |
| Surviving allocation | Warmed counters and JIT/escape-analysis evidence |

A logically Double cotangent may be absent (`nil`). Helper extraction must not
turn it into a primitive parameter, return or local solely from its logical tag.
Public primitive descriptors and successful primitive-array reads can establish
stronger facts. A primitive-array descriptor admits null; its element read only
establishes scalar presence *on normal completion*, without removing null/bounds
checks. Unknown producers retain reference-capable numerical boundaries.

### Selected entry carriers and primitive evaluation

`method-entry/selected-parameter-carriers` projects the actual registered
`invk` interface under the existing definition owner. Historical source and
receiver observations precede analysis and are checked before publication.
The projection retains real parameter Classes and the Object return; it does
not generate an interface, infer presence from tags, or invoke user code.

`intrinsics/primitive-fp-total?` queries a separate facet of the existing
intrinsic table. Its contract covers completed primitive floating arithmetic
and ordered comparisons, including IEEE zero/NaN/infinity behavior. It does not
certify source operand completion, reference unboxing or a generic invocation:
Object/Object division can throw even with boxed Double operands, while the
primitive Double/Double overload is IEEE. Integer overflow/division and absent
contracts conservatively abstain.

These are proof inputs, not enabled source rewrites. Guarded-loop normalization
must additionally establish exact source-entry/call correspondence, lexical
producer facts and safe movement of the predicate, prefix and count. A reference
array Class is not nonnull evidence; reuse of a shape evaluation requires a
dominating successful check on the same immutable array identity. Zero-trip and
false-guard behavior must survive optimization. No serial one-work-item wrapper
substitutes for proving parallel ownership.

Selected scalar producer proofs also require historical source-entry lineage.
A current receiver/source snapshot does not prove that newly edited metadata
describes an already emitted method. The shared strict scalar selector therefore
checks the cold `jit-spec` or warm owned emission against the original source
entry before deriving either presence or arithmetic/conversion completion.
Missing or legacy lineage abstains without forcing JIT compilation.

`checked-selected-primitive-evaluation` has a deliberately bounded
`:completed-fp-scalar` scope. It composes independently completed argument facts
with actual primitive formals and the strict selected body, using the shared
source arithmetic planner and intrinsic totality facets. Nullable/arbitrary
Number inputs and narrowing conversions abstain. Physical Object returns stay
Object even when builtin Float/Double/Boolean presence is established. This is
not global removability, external purity, or a promise against compiler/VM
resource failures, and enables no guarded rewrite on its own.

### Actual return bridges and primitive payload plans

The typed interface's Object result and a primitive computation behind it are
separate facts. The bytecode producer records the actual unguarded `invk` wrapper
edge to its static FP computation, with actual Methods, implementation and body
identity. It also records the body's emitted result category independently of
the method's required return category. A hidden reference-to-FP return conversion
does not qualify merely because the static method declares a primitive result.

`retained-typed-return-bridge` checks that correspondence under the existing
emission guard. `checked-selected-fp-payload` additionally checks a bounded closed
FP leaf using the existing source arithmetic planner and scalar SSA lowerer.
Every effective retained node dtype must agree with the independently computed
primitive carrier; matching only the final result dtype would miss an inserted
Float operation followed by widening back to Double. Numerical tests compare
the actual wrapper and SSA on Float/Double, signed zero, NaN and infinity, and
demonstrate that nested-width counterexample.

This first proof requires an actual owned emission. It neither invokes the JIT
to acquire evidence nor disguises a cold source contract as emitted evidence.
Cold native preparation needs its own explicit source-context proof rather than
a dependency on numerical JVM warm-up.

The returned plan keeps the physical Object result separate from its FP payload.
A parent Object/Object arithmetic operation must retain its Numbers overload;
the proven payload cannot silently select primitive IEEE division instead.
Original argument evaluation/conversion and use-closed box-storage erasure are
additional obligations. These producer observations alone enable no native box
erasure, do not repair the held product transformation, and add no derivative
rule, cache, numerical permission or parallel function/type registry.

Optional proof observations are transactional: an accepted fact contributes to
the existing owner, while a refused query does not create an executable
dependency. Child queries inherit historical observations rather than taking a
fresh snapshot around old output. HVP publication prepares observed pending JIT
receivers through the existing non-evaluating compiler entry under separate
ownership. It then checks the ORIGINAL observations, causing whole-construction
retry after promotion; it never restamps the old closure. Real definition
replacement still invalidates the published derivative.

`normal-return` and selected scalar proofs share historical body/lookup authority.
Pending typed code uses its exact `jit-spec` source with observed current lookup
edges. Warm typed code uses the body actually consumed by its owned emitter,
not current walked metadata or a reinterpretation of raw source. Bare calls in
compiled bodies require original lookup observations, which are also retained
by the new artifact's owner. The emitter records both core and noncore bare
resolution decisions; a negative decision selects code just as a positive one
does. Missing legacy lookup evidence abstains without forcing compilation.

Plain `deftm` declarations freeze the exact Clojure body at function creation,
before dispatch publication. Declaration-specific keys in the existing body
registry keep delayed/interleaved macro expansions from borrowing another
declaration's metadata. This does not solve registry retention: every expansion
now retains its own entry, and repeated evaluation of an expansion prevents a
naive consume-once cleanup. A lifecycle solution remains separate work.

These are sequential correspondence fences, not authentication against forged
compiler-owned metadata or concurrent mutation/ABA guarantees. No guarded-loop
rewrite is enabled here. Internal resident scalar staging also remains distinct
work: nonterminal producer certification, explicit singleton capture loads and
predicate storage encoding must be proved before using that route.

Shared recovery of scalar-cast/read presence is held out until their source
evaluation obligations survive value liveness and DCE. Being present on normal
return does not mean that a null/bounds/conversion failure may be discarded.

Arithmetic emission consumes actual operand carriers, including the return
carrier of each intermediate operation. Reference-carried Numbers must not be
rounded through double merely because a primitive numerical result is desired.
Mixed `Numbers` overloads are semantically significant: Double/Object division
is IEEE, whereas Object/Object division checks zero. A source cast descriptor
alone does not prove that its emitter returns a primitive value.

Direct variadic core arithmetic follows core's nested `nary-inline` operations;
an overflowing inner operation can run before a later argument effect. An
explicit IFn call instead evaluates its arguments before entering the function.
Independent source-oracle tests cover both boundaries rather than assuming they
have the same order. This does not qualify all existing primitive numerical
recipes as complete Clojure semantics: primitive integer division, narrowing
and Character carriers still require their own contracts and qualification.

### Open: large backward-loop materialization

The actual immutable MMM fixture has demonstrated surviving Double and product
allocation. Small closed quadratic controls do not reproduce its row-dependent
allocation, despite Object-returning signatures. A descriptor by itself is not
an allocation measurement. Method size, inlining and escape analysis must be
examined alongside retained loop carries/products and actual boxing sites.

Nullable helper and arithmetic correctness repairs are not an allocation-gain
claim. The small publication slice also does not finish the full MMM zero-trip
case: the ordinary-call walker still inserts inferred primitive operand casts.
Removing those casts exposes existing DCE exceptional-evaluation gaps, including
negative allocation extents. That follow-up must preserve source evaluation
obligations, not weaken exception tests or replace absent gradients with zero.

The intended representation lowering scalar-replaces nonescaping products and
uses separate presence/payload state for proven-safe internal optional scalars.
It materializes reference values at escaping, public or identity-observable
boundaries. Acceptance requires zero-trip and changed-input numerical checks,
identity/effect/exception controls, and matched warmed allocation measurements
on the real model; stable internal port order alone proves no speedup.

## Open: primitive Character completion

Confirmed against commit `c57493ef0ca41056426f22f79fba976d0c5fc88a`, before
the bitwise Long/Object repair, using Clojure 1.12.0:

```clojure
(fn [left right]
  (clojure.core/bit-and (clojure.core/char left)
                        (clojure.core/char right)))
```

At `[7 40]`, independent Clojure source throws `IllegalArgumentException`:
Character is not a supported Numbers bitwise operand. The original bytecode
owner instead returns Integer `0`. The Long-width repair returns Long `0`;
neither is correct Character behavior. Negative inputs additionally expose
the existing unchecked `i2c` conversion rather than checked source conversion.

To reproduce without source rewriting, pass the quoted body above to
`raster.compiler.backend.jvm.bytecode/compile-specialized-class!` in a method
spec with `:name 'run`, `:params '[left right]`, `:return-tag 'Object`,
`:walked-body [body]`, and `:source-ns *ns*`; invoke the returned `run` Method
with `(object-array [7 40])`. Here `body` is the inner bitwise expression, not
the enclosing `fn` form. Compare with `(eval (list 'fn '[left right] body))`.

The producer currently emits `char` as `i2c` with result category `:int`, losing
the distinction between Character and Integer before a consumer sees it.
This belongs in shared physical-carrier/conversion handling, not a bitwise
function-name exception. A fix must qualify checked conversion, actual primitive
char parameter consumers, explicit char-to-int conversion, Object boxing and
argument effect/exception order together. A checked Character-reference result
is a possible representation, but needs compatible consumers and unboxing.

Raw boxed Character rejection is covered by the bitwise differential tests.
Primitive Character construction parity is **not** qualified by those tests or
by restoring the keyed random distributions. Keep this debt open until its
independent source oracle passes; do not restore dtype-only unboxing to hide it.
