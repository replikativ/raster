# Bug: full pretrained-rstr resident decoder fails the GPU fixpoint typedness census

Observed 2026-08-22 while adding durable KV continuations to pretrained-rstr.

## Summary

`pretrained.decoder-gpu/bind-decode!` for Gemma 3 270M fails before allocating or
executing the continuation path. Raster's GPU fixpoint census reports 14 untagged
`raster.par/dp4a` bindings generated by the resident layer program.

This reproduces with both:

- the local Raster `main` checkout at `498f7fc2` (`v0.2.320`); and
- the released `org.replikativ/raster:0.2.320` artifact.

The fail-loud census appears to be doing its job. The likely defect is that the
DP4A emission/template path does not carry the required result tags onto its
intermediate `d1`/`d2` bindings.

## Impact

The full GPU resident decoder cannot bind after pretrained-rstr moves from Raster
`0.2.287` to `0.2.320`. This blocks the real Gemma KV export/import token-exactness
anchor. CPU continuations and model-free GPU transfer/state tests are unaffected.

The narrower `pretrained.decoder-gpu-oracle-test` still passes 2 tests / 9
assertions through the changed contraction routing, so it does not cover this
full-binder path.

## Reproduction

From `/home/christian-weilbach/Development/pretrained-rstr-main`, whose `deps.edn`
pins Raster `0.2.320`:

```bash
clojure -M -e '
(require (quote pretrained.loader) (quote pretrained.decoder-gpu))
(def model
  (pretrained.loader/from-pretrained
   (str (System/getProperty "user.home")
        "/Development/models/gemma-3-270m-it")))
(pretrained.decoder-gpu/bind-decode! model :maxpos 64)
'
```

To reproduce against the sibling checkout instead of the Maven artifact, use
`-M:dev`.

## Actual result

```text
clojure.lang.ExceptionInfo:
fixpoint edge typedness violation on GPU target:
14 non-exempt untagged binding(s) #:raster.par{dp4a 14}
```

Representative bindings from `ex-data`:

```clojure
(d1_α = (raster.par/dp4a
          (long lo_α)
          (clojure.core/aget qinp
            (clojure.core/+ xj_α (long r_α)))
          (long d_α)))

(d2_α = (raster.par/dp4a
          (long hi_α)
          (clojure.core/aget qinp
            (clojure.core/+ xj_α (long 4) (long r_α)))
          d1_α))
```

The complete classification is:

```clojure
{:non-exempt-untagged #:raster.par{dp4a 14}
 :undevirtualized {}
 :target-device :ze:0}
```

The throw is at `raster.compiler.pipeline/record-fixpoint-census!`, currently
`pipeline.clj:630`, called while `compile-gpu-program` compiles the resident
layer from `pretrained.decoder-gpu/bind-decode!`.

## Expected result

The emitted DP4A intermediate bindings carry their integer result type through
the fixpoint edge, the census stays empty, and `bind-decode!` returns a resident
decoder state.

Do not exempt `raster.par/dp4a` from the census: that would hide the exact class
of narrowing/miscompile the new gate is intended to prevent.

## Continuation anchor that found it

The new pretrained-rstr anchor binds Gemma, generates six tokens uninterrupted,
then generates two, range-exports K/V, restores it, generates four, and compares
the token vectors. The failure occurs at the initial `bind-decode!`, before the
new ranged transfer or continuation functions execute.
